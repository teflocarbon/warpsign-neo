# warpsign-neo

Rust port of Python warpsign (https://github.com/teflocarbon/warpsign), aiming at on-device iOS signing plus a cross-platform CLI: a Rust core (`crates/warpsign-core`), Swift bindings (`crates/warpsign-ffi`), a CLI (`crates/warpsign-cli`), the iOS app and WarpSign Companion (`ios/`, XcodeGen), and the manifest Worker (`worker/`). See README.md for the plan and `docs/` for design notes.

## This repository is public

Everything that lands here is public and effectively permanent: code, fixtures, docs, commit messages, issues and pull requests, CI logs, and release assets. Deleting something in a later commit doesn't remove it: it stays in the history, in forks and in caches. Assume anything you write may be read by anyone, and work accordingly.

**Never commit, paste into a commit message, issue or PR, or print in CI:**

- Apple ID details: account names, passwords, two-factor codes.
- Sessions: saved session JSON, cookies (`myacinfo`, `DES…` trust cookies, `dqsid`), `scnt`, `X-Apple-ID-Session-Id`, CSRF tokens.
- Signing identities: `.p12` files, private keys, backup passphrases.
- Real provisioning profiles: they name the team and person, and list device UDIDs and certificates.
- Pairing files (`.rppairing.plist`, `.mobiledevicepairing`): whoever has one can install apps on that device.
- Anything that identifies a real person, team or device: names, emails, team IDs, UDIDs, certificate serials, phone numbers.
- Network logs (`--http-log`, the app's Network Log), even redacted ones, without reading every line first.
- Signed IPAs, and screenshots that show any of the above.

**Data from a real account** (fixtures, test cases, log excerpts in docs or commits) is scrubbed before it's committed: replace team IDs with `ZZZZZ99999`, people with `Test User`, UDIDs with `00008110-000A0B0C0D0E0F10`, zero per-request IDs, and read the diff. Describe what was seen ("seen on a device in October 2026"), not whose device or account.

**Before every commit**, read the staged diff (`git diff --cached`), not just the file list. `.gitignore` refuses the riskiest file types outside `tests/data`, but it's a safety net, not a check.

**If something sensitive is committed anyway**, a follow-up commit doesn't undo it. Tell the owner straight away, and treat the secret as exposed: sign out the session, revoke the certificate, make a new pairing file. Rewriting published history needs the owner's go-ahead.

**CI runs on public runners, with public logs.** Secrets only ever come from GitHub Secrets, are never echoed (no `set -x` near them), and workflows don't run code from forks with access to them (no `pull_request_target` with a checkout of the PR). Releases publish unsigned builds only.

**The manifest Worker is public by design**: it writes a manifest from the bundle ID, title and version it's given, and keeps nothing. Keep it that way: no secrets in `wrangler.toml`, no logging of requests.

## Parity with Python warpsign

- Python warpsign is the reference implementation. Ported logic must reproduce its outputs exactly, quirks included. Encoded bundle IDs in particular must never change, because a changed ID means a new app on the device and lost data.
- Behaviour is pinned by `fixtures/*.json`, generated by `tools/gen_fixtures.py` from a warpsign checkout, and checked by `crates/warpsign-core/tests/python_parity.rs`.
- When porting more of warpsign: add cases to the generator first, regenerate the fixtures, then port until the parity tests pass.
- Do not "fix" a quirk inside a port. Keep the Python behaviour, comment it as such, and raise it separately. Changing behaviour that reaches Apple (portal requests, entitlements, signing) needs testing against a real account and device.

## Checks

Run before committing:

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
```

The iOS apps are built by `.github/workflows/ipa.yml` (and checked by `ios.yml`); there's no Swift compiler outside macOS, so Swift changes are proven by those builds.
